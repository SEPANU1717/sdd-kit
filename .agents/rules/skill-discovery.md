# Skill Discovery

Every SDD step finds the expert skills that apply to the current feature on its
own. Adding a skill folder to `.agents/skills/` is enough; nothing else has to
be edited.

## How a skill declares itself (optional, recommended)

In the skill's `SKILL.md` header:

```yaml
---
name: apple-design
description: ... Use when ...
metadata:
  sdd-steps: specify, plan, implement, review
  sdd-when: the feature adds or changes UI
---
```

- `sdd-steps`: which SDD steps must use it.
- `sdd-when`: the trigger, in plain words.
- `sdd-steps: none` opts a skill out of SDD completely.

## How a step finds skills

At the start of any SDD step:

1. Read `.agents/skills/INDEX.md` (generated by `scripts/sync-skills.*`).
2. List the folders in `.agents/skills/` anyway. Any folder missing from the
   index is new: read the header of its `SKILL.md` directly. Never skip a skill
   because the index is stale.
3. Ignore skills tagged `sdd-steps: workflow` (the `sdd-*` skills themselves) and `sdd-steps: none`.
4. For each remaining skill decide:
   - Tagged: use it when this step is in `sdd-steps` and `sdd-when` applies to
     the feature.
   - Untagged (for example downloaded from GitHub): use it when its
     `description` clearly matches the feature and the step's work. When
     unsure, mention it to the user in one line instead of silently skipping.
5. Apply the "Overrides" table in `.agents/rules/project.md` last: it can force
   a skill on, force it off, or change its steps for this project.

## What a step does with a chosen skill

| Step | Action |
| --- | --- |
| specify | Read it; let it shape questions and recommendations; note influenced decisions in the spec. |
| plan | Follow it in the phases; list it under "Expert skills to apply" with what it must check. |
| implement | Apply every skill the plan lists, plus any newly matching tagged skill (mention it in the report). |
| review | Run its checks on the diff; record findings with the usual severities. |

Always name the skills used in the step's report, for example
"Expert skills: apple-design (review), seo-audit (plan)".

## When a skill and a rule disagree

Project rules and accepted decisions win over general skill advice. Mention the
difference in the report.

## Context loading

- Always read `AGENTS.md`, `constitution.md`, the workflow rule, and the
  communication rule.
- Read project, writing, design, security, database, or deployment rules only
  when their subject is in scope.
- Do not require a full repository map for typo, copy, investigation, or other
  low-risk work.
